Get the app and model ready

You need Windows 10 or 11, Python 3.11 or later, and a local model that supports tool use. Tool use lets the model ask the app to read or write files and perform actions. A model that only chats may describe the right steps without doing them.

  1. Extract the project into a writable folder. Open it in File Explorer, type powershell in the address bar, and press Enter. Use a normal window, not “Run as administrator.”
  2. Run the installer below. Wait for “installed and validated.” It downloads Python dependencies, checks the installation, creates data/config.json, and adds a Desktop shortcut.
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1

In LM Studio, load a tool-capable model, open Developer, and switch on Start server. The default address is http://127.0.0.1:1234/v1. For your first run, load just the model you want to use. Models and LM Studio are separate downloads. Its server guide shows the controls.

Then run this from the project folder, or use the Desktop shortcut:

powershell -NoProfile -ExecutionPolicy Bypass -File .\start-agent.ps1

The launcher normally opens http://127.0.0.1:8765/. Other local model servers need settings described in docs/configuration.md and may differ in compatibility. Blender and extra integrations can wait until this first test works.

Make your first file

  1. Return to the workspace and select New task.
  2. Set Time limit to 0.1 hours. That is a maximum of six minutes; checked work can finish sooner.
  3. Paste the instruction below, or select the first-task example in the welcome screen. Review it, then select Send task.

Create welcome.txt in this task's folder with exactly one line: Task Continuity is ready. Read it back and check that it matches. Use only file tools. Do not browse the web, run shell commands, or change files outside this task folder. Finish by reporting the saved file's full path.

A successful run ends with Completed and a reported welcome.txt. Select Open welcome.txt and check its contents:

Task Continuity is ready.

The file normally lives at data/Tasks/<task-id>/welcome.txt inside this installation. Each task gets its own folder. Its full path appears in the saved progress details; if no output button appears, use that path or the one reported in the conversation.

If the model only explains how to make the file, the test has not passed. See troubleshooting before trying a larger task.

Give the next task a clear finish

Say what you want saved, where it belongs, how it should be checked, and what the agent should leave alone. For example:

Make a simple repair-shop website in this task's folder, using clearly marked sample details. Include services, opening hours, and contact information. Check it at desktop and mobile sizes, fix problems you find, and save run instructions. Do not publish it.

A model that accepts images can review screenshots and rendered previews. Text-only models can work with files, page structure, and tests, but cannot judge images. More briefs are in docs/example-tasks.md.

Time limits range from 0.1 to 72 hours, including 50 hours. Start with a short version of your real task before leaving it overnight.

Pause, stop, or ask for a change

Pause
Stops reasoning. Already-started jobs may keep running, and the existing deadline keeps counting down.
Resume
Continues from saved progress with a fresh budget from now, using the hours you have selected.
Stop
Cancels the task and its owned jobs. Saved files remain available.
Follow-up
Select a saved task, enter the change you want, and select Send follow-up. An active task keeps its current deadline; an inactive task gets a fresh budget.

Only one task controls the computer at a time. Closing the browser tab leaves the agent running.

Find your saved work

Select a task in the sidebar to see its conversation, progress, and reported outputs. The saved progress details include its full folder path. Tasks normally live under data/Tasks; if you name an external project, the changed files can be there instead.

The agent keeps the original brief, checkpoints, job records, and outputs across model-session restarts. Check the actual files before accepting the result.

File-tool backups and logs are bounded, but outputs, downloads, and context archives stay on disk. There is no total storage quota. Check free space and remove old tasks when you no longer need them.

If something gets stuck

Python missing
Install Python 3.11 or later with the python command available. Reopen PowerShell, check python --version, and rerun the installer.
Administrator error
Close that window and open an ordinary PowerShell window from the project folder.
Model unavailable
Check that the local server is running and a tool-capable model is loaded. A saved task keeps its selected model; reload that same model if needed.
No file created
Check that your model supports tool calls through your server. Try the first-file task in a new task. A text answer alone does not show that tools work.
Port occupied
Before launching, change ui_port in data/config.json to an unused port such as 8766. Rerun the launcher and use the address it prints.
App will not open
Run start-agent.ps1 in PowerShell to read the error. Startup details are in data/Logs/supervisor-error.log.

For a setup report, run this from the project folder:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\doctor.ps1

The doctor checks the runtime, server, settings, and optional tools. Missing optional tools do not prevent the text-file test. Remove private paths and task contents from any logs you share when asking for help.

Pick up interrupted work

If the app stops, use the normal launcher again. Eligible interrupted tasks recover from saved work while their deadline remains valid. Completed, paused, blocked, stopped, and expired tasks need Resume or a follow-up.

A task remembers its model. Reload that model if it becomes unavailable, or explicitly change preferred_model in the local settings. Changing the server's model order does not change an existing task's choice.

Before retrying an interrupted action, inspect the files and tracked jobs: it may already have finished. Check a running job instead of launching it again. A changed command needs a new job name.

Before longer work

Keep backups and use files you can recover. The agent runs with your Windows account's permissions and is not a security sandbox. Shell commands and third-party programs do not inherit file-tool backup guarantees.

Keep the computer powered; recovery cannot keep processes alive through power loss or Windows shutdown. Desktop input needs Windows signed in and unlocked. Login, CAPTCHA, purchases, publishing, external messages, and privilege changes need your authorization or action where applicable.

Local model hosting does not keep web requests or configured integrations offline. The interface itself listens only on this computer by default.

This experimental release has not had a full overnight or 50-hour endurance test. Recovery and output checks help, but still inspect the result. See RELEASE-STATUS.md for the checks actually run and their limits.
