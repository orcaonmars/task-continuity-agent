Installation

Requirements:

  • Windows 10 or 11.
  • Python 3.11 or later, available as python in PowerShell.
  • A local model server with streaming responses and tool-call support. LM Studio is the default backend; models are installed separately.

Extract or clone the project into a writable folder. Open PowerShell in that folder. In File Explorer, type powershell in the folder's address bar and press Enter. Run the installer as your normal Windows user:

powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1

The installer creates .venv, installs dependencies, validates the installation, writes local settings to data/config.json, and adds a Desktop shortcut. It refuses administrator execution.

Configuration

In LM Studio, load a model trained for tool use. Open Developer and enable Start server. The default endpoint is http://127.0.0.1:1234/v1. See LM Studio's server documentation.

Tool-call support allows the model to perform actions through the app. Image inspection additionally requires a model and backend that accept images. Text-only models can use files, page structure, accessibility, and background jobs, but cannot perform visual review.

Edit data/config.json to change the endpoint or model selection. With preferred_model empty, a new task selects the first loaded model and retains that selection across restarts. Set it explicitly to choose a specific model or replace a saved selection. Other OpenAI-compatible servers must support compatible streaming responses and tool calls.

The source folder's docs/configuration.md covers providers, automatic model recovery, timeouts, and optional tools. Blender is disabled by default; docs/blender.md covers rendering and optional live control.

Usage

Launch from the project folder, or use the Desktop shortcut:

powershell -NoProfile -ExecutionPolicy Bypass -File .\start-agent.ps1

The launcher starts the watchdog and opens http://127.0.0.1:8765/ by default. Closing the browser tab leaves the agent running.

Select New task, enter instructions, set Time limit, and select Send task. Specify the work folder, deliverables, verification criteria, and restrictions. Budgets range from 0.1 to 72 hours; verified work can finish before the limit.

Example: project review

Replace the path before submitting this optional read-only review:

Review [full project folder path] for reliability defects. Use read-only source inspection; do not edit project files, run project code, install dependencies, or publish changes. Save findings.md in this task's folder with prioritized findings, file references, supporting evidence, and suggested fixes. Distinguish confirmed defects from possible risks and note any checks that require execution. Report the saved path when finished.

This authorizes source inspection and a report in the task folder, without changes to the reviewed project. Additional examples are in docs/example-tasks.md.

Task controls

Pause
Suspends reasoning. Existing jobs may continue, and the deadline keeps running.
Resume
Continues saved work with a fresh budget using the selected hours.
Stop
Cancels the task and its owned jobs. Saved files remain.
Send follow-up
Adds instructions to the selected task. Active tasks retain their deadline; inactive tasks receive a fresh budget.

Only one task controls the computer at a time.

Outputs and recovery

Tasks normally save under data/Tasks/<task-id>/. Select a task in the sidebar and open Saved progress & files for its folder path, checkpoints, and reported outputs. Completed files can appear as Open buttons. An explicitly selected external project can contain the edited files instead.

The original brief, checkpoints, job records, and outputs remain across model-session restarts. Relaunch the app normally after an interruption. Eligible tasks recover while their deadline is valid; completed, paused, blocked, stopped, and expired tasks need Resume or a follow-up.

Inspect existing files and jobs before retrying an interrupted action: it may already have completed. Poll a running job instead of relaunching it. A changed command needs a new job name.

Operating limits

The agent runs with your Windows account's permissions and is not a security sandbox. Keep backups. Shell commands and third-party tools do not inherit file-tool backup guarantees; capability switches do not restrict the account's underlying authority. Login, purchases, publishing, external messages, and privilege changes require your authorization or action where applicable.

Desktop interaction requires an unlocked Windows session. Keep the computer powered; recovery cannot preserve processes through shutdown or power loss. Backups and logs are bounded, but outputs, downloads, and context archives are retained without a total disk quota.

The interface binds to this computer by default. Local model hosting does not keep web requests or configured integrations offline. Runtime data is excluded from the source release; consult docs/publishing.md before sharing an installed copy. RELEASE-STATUS.md records recovery evidence and limits. An overnight endurance run has been completed in maintainer testing; a 50-hour run remains unverified.

Troubleshooting

Run setup diagnostics from the project folder:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\doctor.ps1
Python missing
Install Python 3.11 or later with the python command available. Reopen PowerShell, check python --version, and rerun the installer.
Administrator error
Use a normal PowerShell window.
Model unavailable
Check the server address and loaded model. For an existing task, reload its selected model or set preferred_model explicitly.
No tool actions
Confirm that the model and server support tool calls. A text response alone does not establish tool compatibility.
Port occupied
Set ui_port in data/config.json to an unused port, such as 8766. Relaunch and use the address printed by the launcher.
Interface unavailable
Run start-agent.ps1 in PowerShell to read the error. Inspect data/Logs/supervisor-error.log for startup details.
Time limit reached
Inspect saved outputs, select an additional budget, and use Resume or send a follow-up.

Missing optional tools do not prevent core file work. When reporting a problem, include diagnostics and the relevant error with private paths and task contents removed.
