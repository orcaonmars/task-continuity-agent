Setup

  1. Run install.ps1 as your normal Windows user.
  2. Load a model trained for tool use in LM Studio, or configure a compatible local streaming backend in data/config.json.
  3. Run start-agent.ps1 or the Desktop shortcut. The interface listens on 127.0.0.1; change ui_port if its port is occupied.
  4. Try a small task that writes a text file and reads it back before attempting longer work.

For visual work, use a model and backend that accept image inputs. Blender is optional and disabled by default. Configuration details are in docs/configuration.md in the source folder.

Start a task

Select New task, describe the result, choose a time budget, and select Send task. Include the work folder, expected files, checks that define success, and any boundaries such as preserving originals or keeping the work local.

The budget accepts 0.1–72 hours, including 50 hours for longer projects. Verified work ends early. A larger budget does not make an unsupported model or backend compatible.

Start with a complete first version, then ask for inspection and refinement. The welcome examples cover code, research, and Blender; more detailed briefs are in docs/example-tasks.md.

Controls

Pause
Stops reasoning. Already-started background jobs may continue. The existing deadline still runs.
Resume
Continues from saved progress and starts a fresh budget from now using the hours in the composer.
Stop
Cancels reasoning and the task's owned jobs. Saved progress and outputs remain available.
Follow-up
Select a saved task, enter the next instruction, and select Send follow-up. An active task keeps its current deadline; an inactive task receives a fresh budget.

One task controls the computer at a time. Closing the browser tab leaves the agent running.

Find saved work

Choose a task in the sidebar to see its status, conversation, saved progress, and reported outputs. Its actual folder is shown in the workspace. Tasks normally live under data/Tasks; an explicitly selected external project can contain the edited files.

Checkpoints, original briefs, tool receipts, job logs, and verified results survive model-session restarts. Inspect the actual outputs before accepting a result. File-tool backups and log rotation are bounded. There is no total disk quota: outputs, downloads, and context archives are retained.

Recover a task

If the supervisor stops, use the normal launcher again. Eligible interrupted tasks recover from saved state while their deadline remains valid. Completed, paused, blocked, stopped, and expired tasks need an explicit continuation.

If a task is waiting for its model, reload the model it selected or explicitly change preferred_model. Once a task selects a model, changing the server's model order does not change that choice.

Before retrying an interrupted action, inspect its files and tracked jobs: it may already have executed. Poll a running job instead of launching it again; changed commands need a new job name. Resolve a reported blocker, then use Resume or a follow-up.

Keep the computer powered and check free space. Recovery cannot preserve running processes through power loss or Windows shutdown. Automatic recovery has limits and may need your intervention.

Use recoverable work

The agent uses your Windows account's permissions. It is experimental software and is not a security sandbox. Keep backups; shell commands and third-party tools do not inherit file-tool backup guarantees.

Desktop input needs Windows signed in and unlocked. Login, CAPTCHA, purchases, publishing, external messages, and privilege changes require your direct authorization or action where applicable. Capability switches limit available tool groups, not the account's underlying authority.

See the source folder's README and RELEASE-STATUS.md for setup details, verification evidence, and current limitations.
